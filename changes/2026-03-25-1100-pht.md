# 2026-03-25 11:00 PHT — Schedule Picker UX Overhaul, Pinned Location Geocoding, PlaceSearch Improvements, Admin Logo Update

## Summary
Follow-up to the Week 10 Advanced Booking feature. Replaced the Material3 TimeInput (text-field digits) with a custom scroll-wheel (roller) time picker for a professional ride-hailing UX. Fixed a critical bug where the "Schedule Ride" button stayed locked even after the user followed the "Earliest pickup" hint — root cause was `rememberTimePickerState` not syncing bidirectionally with ViewModel state. Also added reverse geocoding for pinned locations, improved PlaceSearchScreen with "Use current location" and empty states, enhanced the scheduling success dialog, fixed a Compose BOM compatibility issue in ScheduledRidesScreen, and updated the admin web logo.

## Bug Fixes

### Schedule Ride Button Lock Bug
**Problem:** User sets time to match the "Earliest pickup today" hint but the Schedule Ride button remains disabled.
**Root Cause:** Material3 `rememberTimePickerState` only reads `initialHour`/`initialMinute` on first composition — subsequent ViewModel state changes (auto-clamp on day switch) don't propagate to the TimeInput widget. The ViewModel state and TimeInput state become desynchronized. Additionally, `System.currentTimeMillis()` advances between hint display and user action, potentially invalidating the displayed hint.
**Fix:** Replaced TimeInput entirely with a custom `ScrollWheelTimePicker` that is fully driven by ViewModel state via `LaunchedEffect` + `animateScrollToItem()`. Added 1-minute tolerance (29 min instead of 30 min) for UI-side validation to absorb clock drift. Rounded hint time to 5-minute intervals matching picker granularity.

### ScheduledRidesScreen PullToRefreshBox Build Error
**Problem:** `PullToRefreshBox` is not available in Material3 1.2.0 (Compose BOM 2024.02.01) — requires Material3 1.3.0+.
**Fix:** Replaced with plain `Box` + `when` block for loading/empty/list states.
