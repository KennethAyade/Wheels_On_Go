# 2026-03-21 12:00 PHT — Admin-to-User Direct Messaging

## Summary
Implemented admin-to-user direct messaging with a CommentsDrawer slide-over panel. Admins can privately message drivers or riders from the web dashboard — primary use case is KYC clarification (e.g., blurry license) as backup to AI verification. Reuses existing Message model with `rideId = null` (no schema migration). Mobile API endpoints created but mobile UI deferred to future sprint.

## Backend Changes

### New Files
- `apps/api/src/admin-messaging/admin-messaging.service.ts` — Core messaging service:
  - `getThreads(adminId)` — list conversation threads with unread counts
  - `getMessages(adminId, userId)` — get conversation between admin and user
  - `sendMessage(senderId, receiverId, content)` — create message with rideId=null
  - `markAsRead(adminId, userId)` — mark user's messages as read
  - `getMessagesForUser(userId)` — mobile: get all admin messages
  - `replyToAdmin(userId, content)` — mobile: reply to most recent admin
  - `markAdminMessagesAsRead(userId)` — mobile: mark admin messages read
  - `getUnreadCountFromAdmin(userId)` — mobile: unread count
- `apps/api/src/admin-messaging/admin-messaging.controller.ts` — Admin-side endpoints (JWT + ADMIN role guard):
  - `GET /admin/messaging/threads`
  - `GET /admin/users/:userId/messages`
  - `POST /admin/users/:userId/messages`
  - `PATCH /admin/users/:userId/messages/read`
- `apps/api/src/admin-messaging/user-messaging.controller.ts` — Mobile-side endpoints (JWT guard):
  - `GET /messages/admin`
  - `POST /messages/admin`
  - `PATCH /messages/admin/read`
  - `GET /messages/admin/unread-count`
- `apps/api/src/admin-messaging/dto/send-message.dto.ts` — DTO with `content` field
- `apps/api/src/admin-messaging/admin-messaging.module.ts` — Module importing PrismaModule

### Modified Files

## Key Design Decisions
1. **No schema migration** — `Message.rideId` is already optional; admin-user messages distinguished by `rideId = null`
2. **Separate from ChatModule** — Different auth guards (ADMIN role), query patterns, and polling instead of WebSocket
3. **Polling over WebSocket** — 10s interval is sufficient for async admin-user communication; simpler than WebSocket for admin dashboard
4. **Mobile UI deferred** — Backend endpoints ready for mobile integration in future sprint
